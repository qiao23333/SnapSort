# 从 Immich 借鉴什么，而不是把 SnapSort 做成另一个 Immich

> 研究日期：2026-08-23。依据 Immich 官方功能页、官方文档与官方仓库整理。

## 产品边界

Immich 的核心是“自托管照片与视频库”：持续备份、多用户、相册、分享、时间线、地图与统一检索。SnapSort 更有价值的定位不是取代图库，而是“从一堆工作素材到可交付目录”的行动型整理工具：扫描、理解、分组、筛选、命名、搬运和复核。

因此应借鉴 Immich 的底层产品逻辑，但保留 SnapSort 面向工作流、一次任务和文件交付的差异。

## 最值得借鉴

### P0：统一复核中心

把低置信度、疑似重复、C 级素材、识别失败和命名冲突放进同一个待办入口，而不是散落在文件夹、日志和不同工具页。每组提供“采用建议 / 保留两者 / 移入回收站 / 改分类”操作。

Immich 的重复项工具会先自动推荐保留项，并在确认后合并相册、收藏、评分、描述、位置和标签等元数据。SnapSort 可以把推荐规则换成更符合工作素材的指标：分辨率、文件大小、EXIF 完整度、清晰度、人物表情和 ABC 等级。

参考：[Immich 重复项工具](https://docs.immich.app/features/duplicates-utility/)

### P0：真正的任务中心

目前 SnapSort 已有进度条、停止和断点续跑，下一步应把每次扫描、AI 分析、缩略图生成、查重和移动都变成可持久化任务：显示当前阶段、完成数、失败数、耗时，支持重试、继续和取消。

Immich 把上传后的元数据提取、缩略图、机器学习和存储模板拆成后台任务，并提供独立 Jobs 页面。SnapSort 不需要 Redis/BullMQ，单机版用 SQLite + 本地工作线程就够，但可以学习它的任务可见性和失败恢复逻辑。

参考：[Immich Jobs and Workers](https://docs.immich.app/administration/jobs-workers/)、[Immich 架构](https://docs.immich.app/developer/architecture/)

### P1：本地素材索引与统一搜索

建立一个轻量 SQLite 素材索引，持久保存来源指纹、路径、时间、EXIF、标签、描述、CLIP 向量、缩略图状态和处理历史。这样素材预览、查重、增量分类与以文搜图共用同一份数据，不必每个工具重复扫描目录。

搜索页逐步支持：自然语言、人物、地点、日期、路径、文件类型、评分、标签、是否归档和是否已处理。Immich 已验证了“语义搜索 + 精确筛选”结合比只有一个搜索框更实用。

参考：[Immich 搜索](https://docs.immich.app/features/searching/)、[Immich 功能清单](https://immich.app/features)

### P1：非破坏式元数据与只读源

增加“来源只读”模式，把识别结果、评分、描述和标签写入 SnapSort 数据库或 XMP sidecar，而不改原图。需要交付时，再根据模板导出目录。这样用户可以反复调整分类逻辑，不会把原文件越整理越乱。

Immich 的外部图库支持只读挂载，XMP sidecar 可承载描述、评分、日期、位置和标签；这正适合 SnapSort 的本地优先与可撤销定位。

参考：[Immich 外部图库](https://docs.immich.app/features/libraries/)、[Immich XMP sidecars](https://docs.immich.app/features/xmp-sidecars/)

### P1：命名模板先预演，再迁移

把现有重命名预览提升为“计划”：先列出将创建的目录、目标文件名、冲突、跳过和风险；用户确认后执行，并保留可撤销清单。模板改变后只对选定任务或选定素材迁移，不自动重写全部文件。

参考：[Immich Storage Template](https://docs.immich.app/administration/storage-template/)

## 可以后做

- 素材堆叠：连拍、相似构图或同一导出版本折叠为一组。
- 收藏、归档、星级和层级标签，作为筛选与导出条件。
- OCR 搜索，用于截图、票据、PPT 与海报素材。
- 监控文件夹：检测新增和修改，但默认先进入收件箱，不自动移动。
- 文件夹视图与时间线视图切换，兼顾工作目录和个人照片两种心智模型。

## 暂时不要做

- 多用户、账号体系、公开链接和社交分享。
- 手机自动备份、云同步和服务端部署。
- 视频转码、地图、回忆和完整相册系统。
- 为了“技术先进”直接引入 PostgreSQL、Redis 和独立机器学习服务。

这些是 Immich 作为家庭照片服务器的核心，却会稀释 SnapSort 的工作工具定位，并显著提高安装和维护成本。

## 推荐版本路线

1. **v3.5 复核与任务中心**：统一待复核入口、持久任务、失败重试、查重保留建议。
2. **v3.6 素材索引与统一搜索**：SQLite 索引、筛选器、CLIP 向量持久化、文件夹/时间线视图。
3. **v3.7 非破坏式整理**：只读源、XMP sidecar、导出计划、模板迁移预演与完整撤销。

## 作品集表达

不要把它介绍成“我也做了一个照片管理器”，而应表达为：

> 我把真实工作中反复发生的素材整理成本，抽象成一个本地优先的工作流产品；它用 AI 做理解，但把风险控制、人工复核、断点恢复和可撤销放在自动化之前。研究 Immich 后，我没有照搬其家庭图库功能，而是把成熟的任务、索引、搜索和非破坏式元数据逻辑重新裁剪到单机工作工具里。

这比堆功能更能体现产品判断、工程取舍和持续迭代能力。
