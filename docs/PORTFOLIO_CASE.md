# SnapSort 作品集案例说明

## 一句话定位

SnapSort 是一个从真实工作摩擦中长出来的本地 AI 素材整理工作台：它把杂乱图片转成可检索、可复核、可继续使用的素材库，而不是只做一次 AI 演示。

## 为什么公司或团队会在意

它解决的不是“有没有图片分类软件”，而是内容、运营、市场和项目团队经常遇到的共同问题：素材进入团队后缺少统一结构，寻找、命名、筛选、去重和交接都在消耗人工时间。

可迁移到其他岗位的价值包括：

- 从一线问题中识别高频、重复、可自动化的环节；
- 把模糊需求拆成分类、复核、规则、历史、恢复等完整工作流；
- 在 AI 不稳定时设计低置信度复核、失败重试和本地隐私边界；
- 兼顾产品体验、工程可靠性、跨平台交付与实际使用数据；
- 把个人工具逐步变成团队可理解、可评估、可复用的产品资产。

因此，这个案例不需要与下一份工作的行业完全相同。它证明的是一条完整能力链：发现问题 → 定义流程 → 构建工具 → 在工作中使用 → 用证据迭代。

## 核心设计决策

1. 本地优先：图片和路径默认留在用户电脑，AI 通过本地 Ollama 运行。
2. 人机协作：低置信度结果进入待复核，而不是假装模型永远正确。
3. 原文件安全：默认复制，重复文件进入系统回收站，事件整理提供撤销与断点续跑。
4. 工作流优先：分类只是中间步骤，最终输出还包括命名、报告、规则和历史记录。
5. 跨平台一致：不依赖不同系统渲染不一致的 Emoji，字体、图标和文件路径按平台处理。

## 面试展示顺序（3–5 分钟）

1. 用一组真实但可公开的杂乱素材说明问题。
2. 演示选择文件夹、开始分类、低置信度复核和结构化输出。
3. 展示历史数据与“导出项目证据”，说明它确实进入了日常工作。
4. 讲一个失败：例如模型误判、Windows 字体回退或同名文件冲突。
5. 讲修复背后的判断，以及下一轮如何用数据验证。

## 证据清单

应用仪表盘可以导出不含文件名和路径的 Markdown 快照。正式放入作品集前，再补齐：

- 纯手工与 SnapSort 的同批素材耗时对照；
- 至少 100 张素材的抽样准确率和复核率；
- 连续使用 2–4 周的任务数、处理量和失败数；
- 一段 30–60 秒核心流程录屏；
- 一次真实误判和修复前后的对照；
- 如果有同事试用，记录一句具体反馈，而不是泛泛的“很好用”。

## 与个人区和长期资产的连接

SnapSort 不需要变成包揽一切的“大杂烩”。更适合的关系是：

- SnapSort 负责把素材变成结构化资产；
- 个人区负责展示项目状态、使用数据、版本迭代和复盘入口；
- Markdown/Obsidian 保存长文档、决策和失败记录；
- 网站只公开经过确认的案例摘要、截图和可下载版本；
- 未来若形成稳定外部需求，再验证团队版、模板包、定制流程或付费支持。

先证明“自己持续使用且确实节省时间”，再考虑收入模式。真实使用证据会同时服务求职、个人品牌和未来商业化。
