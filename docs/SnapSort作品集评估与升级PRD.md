## 一、一句话定位（求职叙事）

**SnapSort 是一款完全本地运行的 AI 素材整理桌面工具：基于 Ollama 视觉模型，把"一堆杂乱照片"自动变成"按事件成组、按质量分级、按规则命名"的可用素材库，零云端、零 token 费用、隐私不出本机。**

对标市面产品时的差异化（这段话现在 README 里没有，但它是项目的灵魂）：

| 对标产品 | 他们是什么 | SnapSort 不同在哪 |
|---------|-----------|------------------|
| Immich / PhotoPrism（GitHub 6-9 万 star） | 个人相册管理，Web 架构，Docker 部署 | **桌面端单文件运行**，面向自媒体/电商的**生产力素材整理**，不是回忆浏览 |
| Eagle / Billfish | 素材管理，靠手动打标签 | **AI 自动分类 + 事件成组**，免打标签 |
| 云端 AI 整理服务 | 按量收费、照片上传云端 | **本地 Ollama 推理**，隐私零泄露，零持续成本 |

独有卖点（面试可讲的故事点）：
1. **事件成组**：按拍摄时间间隔自动聚类成"事件"，再用 LLM 给事件起名（"三亚团建"），不是简单的文件夹分类
2. **ABC 质量分级**：AI 对每张图打 A/B/C 等级，A 级进精选，C 级待删——这是摄影师的真实工作流
3. **断点续跑**：Checkpoint 机制，几千张跑到一半关机，重开接着跑
4. **完全离线**：视觉模型 llava:13b 跑在本机 Ollama 上

## 三、"思考量"分析：这个项目能证明你什么

面试官/HR 看作品集，本质在问三个问题。SnapSort 目前的回答：

### Q1：能不能独立交付完整产品？（产品能力）
✅ **能，且证据充分。** 从需求（自己整理素材的真实痛点）→ 技术 选型（customtkinter 避免 Electron 体积、Ollama 本地推理）→ 打包分发（PyInstaller + Mac/Win 双平台脚本）→ 版本迭代（v2.2 → v3.x 的 changelog 轨迹），闭环完整。**多数候选人只有 demo，没有"分发给别人用"这一步。**

### Q2：技术决策有没有权衡思考？（工程判断）
⚠️ **有，但全藏在代码里，没人看得见。** 实际存在的权衡点：
- 视觉模型选型：llava:13b（质量）vs 7b/moondream（低配机），做了模型降级链
- 线程模型：tkinter 主线程 + 工作线程 + `_safe_after()` 回调安全（踩过 `main thread is not in main loop` 的坑）
- 矢量化算法：自实现 Marching Squares + Douglas-Peucker 抽稀 + Otsu 阈值，不依赖重库
- 性能：缩略图磁盘缓存、AC 关键词匹配（注：此项在合规卫士，别讲混）
- 断点恢复：`.snapsort_checkpoint.json` 状态机

**问题：这些没有一个字写在文档里。** 面试官不会 reverse engineer 你的代码。

### Q3：代码本身经不经得起看？（代码品味）
❌ **目前经不起。** 点开仓库 10 秒内看到的是：v2.3 的过时 README、根目录的 `__pycache__`、无 LICENSE、复制粘贴的工具函数。**第一印象会否定前两问的全部加分。**

### 结论
> 思考量本身 7 分水平，呈现度 2 分水平。**这个项目最大的问题不是做得不够，而是"藏得太深"。** 升级工作 70% 是"把已有的好讲出来"，30% 才是补短板。

## 五、升级需求规格（PRD 主体）

### 5.1 阶段 1：工程化打底（优先级 P0，约半天）

| # | 需求 | 验收标准 |
|---|------|---------|
| 1.1 | 修复 2 个 P0 崩溃风险 | `auto_sort.py` 事件模式回调全部走 `_safe_after()`；`config.py` 写入改为临时文件 + `os.replace` 原子操作 |
| 1.2 | 抽取公共 `ui/safe.py` | `_safe_after()` 收敛为单一实现，3 处引用 |
| 1.3 | `git init` + `.gitignore` | 忽略 `__pycache__/`、`data/`、`dist/`、`.backup_v2/`、`*.zip`；**首次提交前清理历史脏文件** |
| 1.4 | 添加 LICENSE | MIT（对求职最友好，无传染性） |
| 1.5 | 重写 README（中英双语） | 首屏含：GIF 演示（录 15 秒分类过程）、徽章、一句话定位、差异对比表、架构图、快速开始 ≤5 步 |
| 1.6 | README"设计决策"章节 | 把第三节 Q2 的 5 个权衡点写成短文（每条 3-5 行） |

### 5.2 阶段 2：UI 升级（优先级 P1，约 1-2 天）

| # | 需求 | 验收标准 |
|---|------|---------|
| 2.1 | 仪表盘重设计（方案已出） | 问候头部 + Ollama 状态胶囊 + 主行动卡（含"继续上次任务"入口）+ 趋势统计卡 + 事件封面卡片墙（含 ABC 比例条） |
| 2.2 | SVG 图标替换全部 emoji | 内置单色 SVG 图标集（可在代码内嵌 Path 实现），跨平台渲染一致 |
| 2.3 | 空状态设计 | 无历史记录/无素材时显示引导插画式空状态，而非"暂无分类记录"一行灰字 |
| 2.4 | 暗色模式 | theme.py 增加暗色色板 + 设置页开关 + 记忆偏好 |
| 2.5 | 目录扫描不阻塞 UI | `image_count_and_size()` 移入后台线程，仪表盘显示骨架占位 |

### 5.3 阶段 3：质量背书（优先级 P1，约 1 天）

| # | 需求 | 验收标准 |
|---|------|---------|
| 3.1 | pytest 核心测试 | 覆盖：BatchRenamer 命名规则（含自定义 pattern）、事件时间聚类、config 原子写、Ollama 不可用时的降级路径（mock） |
| 3.2 | GitHub Actions CI | push 触发：lint（ruff）+ 测试 + 双平台打包冒烟；README 挂徽章 |
| 3.3 | ruff + 类型注解 | 核心模块（core/）补 type hints，ruff 零告警 |
| 3.4 | 代码去味 | 消除 P2 项：内联 `__import__`、临时文件泄漏、future.result() 裸奔 |

### 5.4 阶段 4：发版与传播（优先级 P2，约半天）

| # | 需求 | 验收标准 |
|---|------|---------|
| 4.1 | v4.0 Release | tag + Release Notes（中文为主），附 Mac/Win 双平台安装包 |
| 4.2 | GitHub Topics 与 SEO | `ollama` `ai-photo-organizer` `local-first` `privacy` `python` `customtkinter`；简介含关键词 |
| 4.3 | 提交渠道 | Ollama 官方 awesome-list、V2EX/即刻/小红书独立开发者话题、r/ollama（英文帖） |

### 5.5 非功能需求

- **性能红线**：10,000 张目录扫描 ≤ 30s；UI 任何操作不冻结超过 200ms
- **降级要求**：未安装 Ollama 时应用完整可开，AI 功能显示引导安装（现有行为保持）
- **兼容**：macOS 12+ / Win10+；Python 3.9-3.13
